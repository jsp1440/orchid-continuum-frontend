# Orchid Continuum Live Completion Ledger

This branch introduces the machine-readable foundation for a near-real-time Mission Control completion table.

## Canonical feed

`public/data/oc-live-completion-ledger.json`

GitHub is the source of truth. The feed is intended to be regenerated by Portfolio Steward from issue, PR, workflow, lease, completion-receipt, owner-gate, and Budget Governor state across:

- `jsp1440/orchid-continuum-frontend`
- `jsp1440/orchid-calyx-backend`
- `jsp1440/Orchid-Continuum-Brain`

## Required behavior

1. Never mark an item complete without evidence.
2. Every completion gets a stable monotonically increasing ledger ID.
3. `oc-running` leases populate RUNNING; eligible leaves populate QUEUED; protected boundaries populate OWNER_GATE; genuine dependencies populate BLOCKED.
4. A completed or blocked lane must release capacity and Portfolio Steward must immediately seek the next eligible leaf.
5. Budget Governor spend and remaining ceiling are part of the same feed.
6. The public dashboard may poll this feed every 15–30 seconds; it must not need a human or LLM to redraw the table.
7. Google Docs/Sheets are mirrors/history, not the operational database.
8. No production deployment, main merge, credential mutation, scientific/taxonomy activation, or destructive operation is implied by this feed.

## Next implementation slice

Add a generator that consumes GitHub state/completion receipts, writes the feed deterministically, and a Mission Control table that polls it. Wire the generator to existing Portfolio Steward/control-plane events rather than creating a second orchestrator.
